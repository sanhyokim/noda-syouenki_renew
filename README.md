# 野田の消煙機 JL-8A — LPリニューアル

現行LP（https://shoenki.duct-noda.com/ 、WordPress + Elementor）のデザインと構成をそのまま活かし、WordPress を使わない静的サイトとして作り直したものです。
ライブラリやビルドは使わず、HTML / CSS / JavaScript だけで動きます。現行サイトにはなかった「仕組み」セクション（集塵シミュレーション）を加えました。

![PC ファーストビュー](docs/preview/pc-01-hero.jpg)

## プレビュー

リポジトリ直下でローカルサーバーを立てて開いてください。

```sh
python3 -m http.server 8000
# または
npx serve .
```

→ http://localhost:8000/

スクリーンショットは [`docs/preview/`](docs/preview/) にあります。撮影環境に日本語Webフォントが無いため代替フォントで表示されていますが、本番では Noto Sans JP（現行LPと同じ書体）が読み込まれます。

## 現行LPから変えたこと

色（紺 #15324a・オレンジのボタン・青 #3498db）、ロゴ、写真とイラスト、セクションの順番、文章は現行LPのままです。そのうえで、見にくい・使いにくいところを直しました。

**見やすさ**

- 本文を 16〜17px・行間 1.85 に揃えました（現行は 14px 前後で行間が詰まっていました）。
- 見出しは文節ごとに改行位置を決め、「放置し／ていませんか？」「対策で／きます。」のような変な位置での改行をなくしました。
- 背景に薄く出ていた本体の3Dモデルをやめ、文字の後ろは無地にしました。
- ファーストビューは、写真の上に文字が重なっていたのを、左に文字・右に写真の2段組みにしました。スマホでは写真の下に文字を置いています。
- 「POINT01〜03」の丸や導入店舗の帯は、画像に焼き込まれていた文字を本物の文字にしました。くっきり表示され、検索エンジンにも読まれます。
- ボタンの文字を濃い色にして、オレンジの上でも読みやすくしました。
- 導入実績の3項目は、数字を大きく見せるカードにしました。

**使いやすさ**

- スマホの左下に重なっていた「お電話」「LINE問合せ」の丸いボタンを、画面下の固定バー（お電話 / LINE / 無料で資料請求）に変えました。本文に重なりません。フォームを入力している間は自動で隠れます。
- 「スマホ表示で Loading 3D Model: 0%」の文字が出ていた問題もなくなりました。
- ヘッダーに「特長・仕組み・導入事例・ご利用の流れ・よくある質問」へのリンクを付けました（PC）。
- 稼働動画は、現行では白い箱だけが表示されていました。サムネイルと再生ボタンを表示し、押したときにだけ YouTube を読み込みます。
- よくある質問は開閉式のまま、「設置・工事」「費用・メンテナンス」「導入・ご契約」「製品・仕組み」の4つに分けました。PCでは左に分類の目次（読んでいる分類に印が付きます）と、電話・フォーム・LINEの問い合わせ欄を固定表示し、スマホでは分類ボタンを上に、問い合わせ欄を最後に置いています。答えには「A」を付け、開くときはなめらかに広がります（対応ブラウザのみ。動きを減らす設定では動きません）。

## 全国販売に向けて

九州・中国地方に限らず全国で販売するため、地域が限られて見える表現を見直しました。

- 導入店舗の帯から地域名（福岡・熊本）を外し、業態だけにしました。九州以外の方が「九州限定」と受け取らないようにするためです。
- ファーストビューの帯に「全国対応」を加えました。
- よくある質問に「対応エリアはどこまでですか？」を加えました（13問）。質問には地域名を出さず、答えで「全国に対応」「九州・中国地方以外では提携業者が設置工事と毎月のメンテナンスを担当」と説明しています。
- 「ご利用の流れ」の下に、同じ内容の注記を入れました。
- 資料請求とお問い合わせのフォームに「店舗の所在地（都道府県）」を加えました。
- 説明文（meta description）と構造化データ（対応エリア：日本）に全国対応を反映しました。

## 公開の手順（コアサーバーの WordPress と差し替える）

今のLP（shoenki.duct-noda.com）は、コアサーバー（LiteSpeed）の WordPress で動いています。同じサーバー・同じURLのまま、公開フォルダの中身を WordPress から新しいファイルに入れ替えます。DNS（ドメインの向き先）は変えず、SSL（https）もそのまま使えるので、検索順位もそのまま引き継がれる見込みです。作業にはコアサーバーのコントロールパネル（またはFTP）に入れる方が必要です。

**事前準備（今のサイトはそのまま）**

1. **フォームは設定なしで使えます**（下の「フォームの送信先」）。送信元は今の WordPress のフォームと同じ info@duct-noda.com にしてあります。
2. **アップロードするファイルをそろえる**：`index.html` `404.html` `.htaccess` `robots.txt` `sitemap.xml` と、フォルダ `assets/` `company/` `contact/` `privacypolicy/` `transmission/` `form/` です。`v2/` `wordpress/` `docs/` `README.md` `_headers` は上げません。`.htaccess` は名前が「.」で始まるので、パソコンでは隠しファイルになっていることがあります。
3. **広告の成果の数え方はそのままで大丈夫です**：資料請求の送信後は、今と同じサンキューページ（`/transmission/`）に移ります。広告や Google アナリティクスで、このページの表示を成果として数えている場合も、設定を変えずに数えられます。
4. **試しに置いて確かめる（おすすめ）**：公開フォルダの中に `_new` フォルダを作って 2. のファイルを入れ、`https://shoenki.duct-noda.com/_new/` で表示と、フォームのメール（自動返信と通知）が届くかを確かめます。表示されれば `.htaccess` もこのサーバーで動いています（動かない場合もエラーになるのはそのフォルダだけで、今のサイトには影響しません）。確認できたらフォルダごと削除します。

**差し替え（今のサイトが新しいLPに変わります。日時はご判断ください）**

5. **バックアップを取る**：公開フォルダの中身をすべてパソコンにダウンロードし、WordPress のデータベースも書き出して（コントロールパネルの phpMyAdmin、またはバックアップ用プラグイン）保存します。
6. **WordPress のファイルを公開フォルダの外へ移す**：ファイルマネージャーか FTP で、公開フォルダの中身を、公開フォルダの外に作ったフォルダ（例：`wp_backup_20261020`）へ移動します。削除ではなく移動にしておくと、すぐに戻せます。
7. **新しいファイルをアップロードする**：2. のファイルを公開フォルダに入れます。`.htaccess` は WordPress のものと置き換わります。
8. **すぐに確認する**
   - トップ・会社概要・プライバシーポリシー・お問い合わせが表示される。`http://` で開くと `https://` に変わる
   - 資料請求とお問い合わせを1件ずつ送り、自動返信と通知メールが届くかを確かめる（迷惑メールのフォルダも）
   - 稼働動画がその場で再生される
   - 資料請求の送信後に「資料のご請求ありがとうございます」のページ（`/transmission/`）が出る
   - 旧URL（例：`/elementor-768/`）がトップページに移り、存在しないURLでは「ページが見つかりません」が出る
   - タグマネージャーのプレビューか、GA4 のリアルタイムで計測が届いている

   表示がおかしい場合は、新しいファイルを消して 6. で移したファイルを戻せば元どおりです。「リダイレクトが多すぎます」と出る場合は、`.htaccess` の https への転送（`RewriteCond %{HTTPS}` からの3行）を消してください。

**差し替えのあと**

9. **Search Console**：「サイトマップ」に `sitemap.xml` を送信し、トップページを「URL検査 → インデックス登録をリクエスト」します。旧サイトマップ（`sitemap.rss` など）は新しい `sitemap.xml` に転送されます。
10. **WordPress を片付ける**：1〜2か月問題がなければ、移しておいた WordPress のファイルとデータベースを削除します。使わない WordPress を置いたままにすると、更新されずに攻撃の入口になりやすいためです。バックアップはパソコンに残しておきます。

**`.htaccess` でしていること**：`http://` から `https://` への転送、WordPress 時代のURL（`/野田の消煙機/` `/elementor-768/` `/投稿1/`〜`/投稿3/` `/category/お知らせ/` `/feed/` など）からトップページへの転送（301）、旧サイトマップから `sitemap.xml` への転送、公開しないフォルダを見せない設定、存在しないURLで `404.html` を表示、セキュリティとキャッシュのヘッダー。

Cloudflare Pages・Netlify などに移す場合は `.htaccess` の代わりに `_headers` が使われ、DNS の切り替えが必要になります。PHP が動かないので、フォームの送信先も別に用意する必要があります。

## フォームの送信先

資料請求（`index.html`）とお問い合わせ（`contact/index.html`）のフォームは、同じサーバーの [`form/send.php`](form/send.php) に送られます。WordPress のフォームと同じく、コアサーバーから直接メールを送るので、Google などの外部サービスの設定は要りません（PHP が動くサーバーなら動きます）。送るメールは次の2通です。

1. 担当者への通知メール（件名は「【野田の消煙機LP】資料請求がありました［福岡県］○○ 様」の形で、本文にも消煙機のLPのどのフォームから来たかを書きます。返信するとお客様に届きます）
2. お客様への自動返信メール（資料請求は Box のダウンロードリンク、お問い合わせは受付確認と「資料はお送りしていません」の案内）

設定はファイル先頭にまとめてあり、すべて設定済みです。通知先（`NOTIFY_TO`）は info@noda-duct.com・koroyasu@duct-noda.com・azuma@duct-noda.com・nagamizu@duct-noda.com の4件、お客様からの返信先（`REPLY_TO`）は info@noda-duct.com、資料のURL（`DOWNLOAD_URL`）は Box の共有リンクです。送信元（`FROM_EMAIL`）は、今の WordPress のフォームと同じ info@duct-noda.com です（2026年10月18日にご提供）。

いたずら対策として、ほかのサイトからの送信は受け付けず、同じ接続元からの送信は10分間に5件までにしています。`data-endpoint` を空にすると「プレビュー」として完了画面だけを表示し、実際には送信しません（チェック用のプレビューはこの状態です）。

## 現行サイト（WordPress）への部分移植

[`wordpress/elementor-shikumi.html`](wordpress/elementor-shikumi.html) は「仕組み」セクションだけを、現行サイトの Elementor に載せるための部品です。中身をすべて HTML ウィジェットに貼り付けると動きます。静的サイトへ移行する場合は不要です。

- 固定ヘッダーの高さ（WordPress の管理バーを含む）は自動で読み取ります。ずれる場合は `<section class="nesp" data-offset="70">` のように指定できます。
- スクロールに合わせた固定表示ができない場合は、3つの段階を自動で繰り返し再生します。
- シミュレーションの中身は `assets/js/site.js` と同じです。どちらかを直したら、もう一方も合わせてください。
